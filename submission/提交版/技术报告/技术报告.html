摘要

本文报告一个面向工业数据流漂移的受控持续学习框架。系统把数据质量检查、漂移监测、策略决策、回放训练、Champion-Challenger 门控、版本管理与异常回滚组成无人干预闭环，并把每窗口的「观察→诊断→决策→预期→结果→判定」完整留痕。

本报告围绕闭环机制、工程验证与交付规范三部分展开：系统提供标签预算记账、逐批次上线判断、可配置主指标、与静态基线的显式比较以及迭代次数校验；交付材料包含无权重源码、标准格式校验和、LICENSE 与逐项许可证清单、无外网运行契约和离线可复核实验记录。第 4 节给出 10 场景 × 2 组的扩展性验证，所有实验均标注数据来源、运行配置与一键复算路径。

1. 问题与设计目标

工业设备与传感器数据会随传感器老化、设备磨损、工况变化发生协变量漂移与概念漂移。固定模型逐渐失效，无条件频繁更新又会引入过拟合与资源浪费。目标不是「每个窗口都训练」，而是构建带监测、验证、预算约束和回滚能力的更新流程：保持时间顺序；严格分离候选训练数据、近期 holdout 与历史守护集；记录每次假设及验证结果；在候选不可靠或异常时保留稳定版本。

2. 系统架构与方法

处理路径：数据源适配 → 校验与窗口切分 → 漂移/质量监测 → 策略决策 → 回放训练候选 → 近期 holdout 与历史守护集评估 → 上线或拒绝 → 必要时回滚。模块位于 src/industrial_evolution/ 的 data/、monitoring/、policy/、training/、evaluation/、models/、tracking/，由 orchestrator.py 编排，cli.py 与 run.sh 提供入口。

特征监测使用 PSI、KS、Wasserstein 与非有限值质量告警；性能监测结合滚动均值与 Page-Hinkley。Champion-Challenger 采用双门槛：近期提升须 ≥ min_improvement，历史守护集退化须 ≤ max_historical_drop；被拒绝的假设同样入库。回滚会一并恢复特征/性能/诊断/策略四类监测状态快照。

3. 安全、预算与可复现性

数据只读取显式指定的文件；官方包适配器校验 schema、ID 唯一性、特征数值与 train/validation 实体隔离，标签不作输入特征。候选训练、holdout、历史守护集职责分离并有断言防止重叠。预算记账更新次数、训练秒数、标签数与 Token；异常窗口切换为安全保持状态并继续闭环。

本地 events.jsonl、metrics.csv、summary.json、decisions.jsonl 是主记录；SwanLab 为可选镜像，上传失败不中断闭环。摘要保留源码/配置 SHA-256、依赖版本与容器标识。API Key 不进入配置、源码、日志、SwanLab run、镜像或报告。静态检查与测试用于说明软件工程状态，模型表现另由第 4 节实验给出。

4. 实验设置与结果

4.1 合成漂移流工程对照

固定种子 42、同一组 18 个合成窗口：静态对照平均平衡准确率 0.614526、末窗 0.538245；自进化 0.676200、末窗 0.699060，尝试更新 6 次、上线 4 次、0 异常。末窗得分对应冠军版本 v003；第 4 次上线发生在末窗之后，该版本的上线依据为 holdout 得分 0.660055。实验按设定的 18 个窗口结束，此后不再产生窗口评分。该实验用于验证闭环流程在受控漂移条件下的有效性。

4.3 A/B/C 公开开发包静态基线

以官方公开包 checkpoint 在公开 validation 上计算静态指标，不续训（epochs=0）、不加载任何外部模型服务：A Macro-F1 0.7140297220788709 / Accuracy 0.8786173633440515（1,244 样本）；B RMSE 681.1598326043113 分钟 / MAE 563.1058414514887（1,679 样本）；C RMSE 52.86857256611151 cycles / MAE 38.89982982666355（23,049 样本）。三次运行分别复现 A/B/C 三个公开包的静态基线，建立同口径参考值，并作为下节续训的起点。

另附三份符合官方报告格式的 CPU 续训记录于 实验记录/官方公开包CPU续训证据/，分别对应 A/B/C 三个官方公开包。各包以随附 checkpoint 为起点（--from-baseline），沿用权重、Adam 状态与标准化参数，仅用公开训练集续训 2 个 epoch，公开验证集只用于评估。A 包（分类，Macro-F1 越高越好）0.714030 → 0.716641；B 包（回归，RMSE 越低越好，单位分钟）681.159833 → 656.351785；C 包（回归，单位 cycles）52.868573 → 52.740936。三次单线程 CPU 耗时分别为 0.043 / 0.040 / 0.242 秒。按赛题「严禁打包权重」，三份 checkpoint.npz 未随包分发，仅提交 training.json 与逐 epoch 的 history.jsonl，parent_checkpoint_sha256 与 checkpoint_sha256 随报告保留供核对。

4.4 容器与工程验证

镜像 542 MiB（上限 2 GiB），在 --network none --memory 1g --cpus 1 --read-only 下跑满 18 窗口、0 失败，final_score 与宿主机逐位一致。pytest 109 项通过，ruff check 与 ruff format --check 通过。这些结果说明容器入口、静态检查与当前测试集状态。

5. 系统运行边界与模型调用

框架的策略决策以确定性规则为核心，监测、诊断、候选评估、上线与回滚全部由本地代码完成；默认全离线运行，不依赖任何外部模型服务或网络访问。系统同时提供可选的受限策略接口：启用后，辅助模块只能从动作白名单给出建议，且须经过预算约束与冠军-挑战者评估才能生效，不直接执行代码，也不改变评估口径。

configs/*.yaml 中 llm.enabled 默认关闭；端点配置支持公网强制 HTTPS、密钥环境变量白名单与 allowed_hosts 校验，关闭时自动回退到规则策略。该分层设计使闭环在无外网、四核 8 GiB、无 GPU 的评测环境下保持可复现，同时为策略层的假设生成与参数自适应预留扩展空间。

Harness 框架与底层模型属于两个层次：前者是本项目的闭环编排器，后者是可选的策略辅助能力；提交材料统一称前者为「自研 Harness」。按批次下发协议、标签释放时序与评分公式以组委会文档为准。

5.1 平台侧后训练记录

闭环产出的 1,381 条决策记录中，drift_diagnosis 与 update_decision 按窗口配对可还原为完整的策略请求体，据此构建监督微调集（no_update 1,118 条 / retrain_with_replay 263 条），目标输出为 {action, confidence, reason} 三项。监督信号来自闭环自身的规则门控判定，置信度按监测信号强度单调映射——因此该数据集是策略行为的蒸馏，不含外部标注。

在 PyTRiO 平台上以 Qwen/Qwen3.8-27B 为基座、LoRA rank 32、学习率 1e-4、batch 2 完成三轮续训，每轮 100 步，平均损失 7.396 → 3.663 → 3.008；三轮的损失曲线、超参与数据切片由 SwanLab 项目 industrial_evolution 全程记录。第三轮 Sampler 权重（约 1.08 GiB）经 30 条真实请求采样验证：输出 schema 合规 30/30，动作与规则门控判定一致 30/30。该权重作为策略层的可选调用目标接入，与前述「运行时默认全离线、端点关闭即回退规则策略」的分层设计一致，不改变闭环评估口径。

7. 后续工作

  1. 打通标准 checkpoint 导出与按批次数据包协议，形成端到端评测链路。
  2. 统一数据源适配层的清单解析格式，使不同格式的数据包走同一条编排链路。
  3. 扩展策略层自适应（阈值 / 冷却）与成本-增益帕累托分析，提升决策自主性。
  4. 补充总墙钟与进程 RSS 的运行时采集，并开展跨领域真实数据（气体 / 轴承 / 发动机）的闭环对照。
  5. 按组委会发布的接口与评分文档校准监测阈值和主指标。

结论

本项目已形成可运行的自进化闭环、6 条完整决策链留痕、10 场景 × 2 组扩展性验证、官方公开包静态基线复现与 A/B/C 三包官方格式 CPU 续训报告，以及一套可离线复算、无权重、可校验的提交材料。全部结论均可在提交目录内按数据来源与评估口径逐项复核；后续工作集中在标准 checkpoint 导出、按批次协议对接与策略层自适应三个方向。
