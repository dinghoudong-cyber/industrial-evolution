## 2. 评测机导入（无外网）

```bash
# 1) 导入离线归档
docker load -i industrial-evolution-school-2026-11-12.tar

# 2) 确认镜像存在并记下 REPOSITORY:TAG
docker images | grep industrial-evolution

# 3) 完整性核对（与提交材料一致）
sha256sum -c ../SHA256SUMS.txt
```

> **导入协议待平台侧确认**：本归档是 OCI layout，而非经典 `docker save` 的 `<id>/layer.tar` 结构。Docker Desktop 4.98 / Engine 29.9.2 可导出该格式；不同评测机 Docker/containerd 版本对 `docker load -i` 接受 OCI layout 的支持存在差异。**提交前必须在与评测机同版本的环境中实际跑一次上面第 1 步**，并把输出（含 `Loaded image:` 行）写进《提交前验证记录》。若不被接受，可选方案：用 `skopeo copy oci-archive:<tar> docker-daemon:<tag>` 转换，或请组委会提供导入方式；不要临时在评测机上 `docker build`。

## 3. 离线运行契约（四核 8 GiB / 无外网 / 无 GPU）

```bash
# 环境变量统一由 run.sh 透传，评测方不需要改 YAML、不需要知道内部 python 调用。
IMAGE=industrial-evolution:school-2026-11-12
OUT=$(pwd)/out && mkdir -p "$OUT"

# 3.1 环境自检（依赖、端点、输出目录可写性）；--strict 时不通过即非零退出
docker run --rm --network none --memory 8g --cpus 4 \
  -v "$OUT:/app/runs" "$IMAGE" check --strict

# 3.2 记录通道自检：真写一条标量与一条文本，确认看板/离线落盘可用
docker run --rm --network none --memory 8g --cpus 4 \
  -v "$OUT:/app/runs" "$IMAGE" record

# 3.3 合成漂移流闭环演示（18 窗口，固定种子）
docker run --rm --network none --memory 8g --cpus 4 \
  -v "$OUT:/app/runs" "$IMAGE" demo

# 3.4 正式数据流：按原始行顺序切窗，绝不打乱时间顺序
docker run --rm --network none --memory 8g --cpus 4 \
  -v "$DATA_DIR:/data:ro" -v "$OUT:/app/runs" \
  -e IE_CSV=/data/stream.csv -e IE_TARGET=label \
  -e IE_INITIAL_SIZE=1000 -e IE_WINDOW_SIZE=200 \
  "$IMAGE" csv
```

`demo` 的**已验证下限**是 `--network none --memory 1g --cpus 1 --read-only`：18 窗口全部完成、0 失败、`run_status=complete`、`final_score` 与宿主机逐位一致（0.69906）。因此在四核 8 GiB 下资源充裕。上面统一用 8g/4 核写，是把评测约束显式写成可验收契约。

### 产物与 SwanLab 离线记录

所有产物写入 `-v` 挂载的 `out/<run_id>/`：

- `events.jsonl`、`metrics.csv`、`summary.json`、`decisions.jsonl`（每批次上线/不上线判断）、`models/registry.json`；
- 镜像默认 `IE_SWANLAB=1` + `IE_SWANLAB_MODE=offline`，评测机无外网时记录落盘到 `out/.swanlab/`，**不产生可分享链接**。可分享的公开链接应由提交方在联网环境同步后提供，见《实验记录链接》与《SwanLab 记录公开性整改说明》；
- 上传失败不中断进化闭环；本地 `out/<run_id>/` 永远是主记录。

### 模型权重不随包分发

提交目录内 `镜像/runs/run-20261112-073217-ae2d99/models/` **只有 `registry.json`**（版本链与得分元数据）。`v000~v004.joblib` 已按「严禁将模型权重打包进提交包」移出，仅本机 `runs/evidence-models/` 留存用于复核；`registry.json` 中 `weights_included=false`、各版本 `path=null`。运行 `demo` 会在挂载目录内**重新生成**权重，这是评测运行产物，不属于提交包内容。

## 4. 为什么不能从源码 `docker build`

`Dockerfile` 第 22–23 行有两处 `pip install --index-url "$PIP_INDEX_URL" -r …`，构建期必须联网。`requirements.lock` 的 16 个核心依赖已精确 pin，但 `requirements-extras.txt`（openai / swanlab）使用版本区间，重建也不保证字节级一致（镜像内实际为 OpenAI SDK 3.49.0、SwanLab 0.10.5，本机开发为 3.41.0 / 0.10.4）。

**因此提交的是已冻结的镜像归档，复现路径是 `docker load` + 上面的离线运行命令，不是 `docker build`。** 源码归档用于审阅与审计，不用于在评测机重建镜像。

## 5. 源码归档范围与复现

`../源码/industrial-evolution-source.zip` 由 `打包源码.py` 生成，包含 `src/`、`configs/`、`tests/`、`tools/`、`docs/`、`Dockerfile`、`run.sh`、`LICENSE`、`pyproject.toml`、`requirements*.txt`、`README.md`、`.env.example` 等；排除 `.venv/`、缓存、`runs/`、`datasets/`、`official/`、`submission/`、任何 `.env` 与密钥。源码归档与镜像基于同一源码树。

```bash
# 归档完整性
sha256sum -c ../SHA256SUMS.txt

# 源码侧静态验证（开发机，需 Python 3.10+ 与 dev extras）
python -m venv .venv && .venv/bin/pip install -e ".[dev]"
.venv/bin/python -m pytest
.venv/bin/python -m ruff check src tests
.venv/bin/python -m ruff format --check src tests
```

重新生成源码归档（会改变 zip 的 SHA-256，需同步重算 `SHA256SUMS.txt`）：

```powershell
.\.venv\Scripts\python.exe "submission\提交版\打包源码.py"
```

## 6. 运行边界

- 本阶段**不接入**平台模型服务：Qwen3.8 27B / 4B 在企业赛阶段才提供，当前 Harness 的策略决策由规则门控完成，LLM 调用 0 次、Token 0。配置模板中的 `QWEN3_8_MODEL_ID` 是占位符，不是真实 served model ID。
- 本镜像是**自研 Harness（`EvolutionOrchestrator`）** 的可运行载体，不是已接入比赛专用 Harness/SDK 的证明。正式平台入口、批次下发协议、标签释放时序与评分公式以组委会文档为准。
- `demo` 使用合成漂移流，只是工程闭环验证；A/B/C 公开包静态基线只说明本地兼容性。两者都不是平台成绩。
