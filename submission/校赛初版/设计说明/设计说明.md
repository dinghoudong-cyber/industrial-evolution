# 工业模型自进化框架设计说明

**队伍**：会赢的，对不队（北京印刷学院）　**版本**：提交版（2026-11-14）

## 1. 系统定位

本项目面向工业数据流中的特征分布漂移与任务性能衰减，设计并实现一套可复现、可审计的持续学习闭环框架。系统在本地 CPU 环境中，把数据接入、漂移监测、策略判断、候选训练、对照验证、版本登记与回滚串成一条无人干预的流程；每一次更新都保留「观察 → 诊断 → 假设 → 实验 → 判定」的完整证据链。

框架以自研 Harness `EvolutionOrchestrator` 为核心，命令行入口位于 `src/industrial_evolution/cli.py`，容器入口位于 `run.sh`。全流程默认离线运行，不依赖外部模型服务，在无外网、四核 8 GiB、无 GPU 的评测环境中即可完成，训练产物由评测运行时现场生成。

## 2. 总体数据流

```text
有序数据流
   ↓
数据校验与窗口切分
   ↓
特征漂移 / 性能漂移 / 标签与数据质量监测
   ↓
规则策略决策（可选受限策略模块提供建议）
   ↓
回放集训练候选模型
   ↓
近期 holdout + 历史守护集对照
   ├── 满足门槛 → 登记新版本
   └── 未满足门槛 → 拒绝候选，保留冠军
                         ↓
                   运行状态与实验记录
```

主编排流程位于 `src/industrial_evolution/orchestrator.py`。各模块按职责拆分在 `data/`、`monitoring/`、`policy/`、`training/`、`evaluation/`、`models/` 与 `tracking/` 目录中，便于单独复算与替换。

## 3. 关键设计

### 3.1 数据接入与安全边界

CSV、合成流与公开开发包各自通过数据源适配器进入统一流接口。公开包校验路径检查字段、数值、实体隔离和特征顺序；评估路径仅读取调用方显式指定的 JSONL，只读取输入特征并输出预测，不读取标签。

训练数据、近期 holdout 与历史守护集承担不同职责：候选训练只使用训练/回放数据，近期 holdout 用于检查本窗收益，历史守护集用于防止对既有表现造成过大回退，三者以断言保证互不重叠。标签按首次访问去重**记账**，默认 `label_budget_mode: count_only`，标签配额记账与窗口推进解耦；`enforce` 模式保留给需要模拟配额的本地实验。运行摘要记录数据与 checkpoint 哈希、源码/配置 SHA-256，并在 `vs_official_baseline` 中做同口径基线比较，口径不一致时显式不计算增益。

### 3.2 漂移监测

系统提供 PSI、KS、Wasserstein 等特征分布监测，以及滚动性能变化、Page-Hinkley 与标签分布监测，并对非有限值等数据质量问题给出告警。分数定义、主指标与判定阈值均可通过配置按任务类型校准（`validation.score_metric` 支持 `macro_f1`、`negative_rmse`、`balanced_accuracy`），便于在不同工业任务间复用同一套闭环。

### 3.3 策略决策与可选辅助模块

策略决策以确定性规则为核心，监测、诊断、候选评估、上线与回滚全部由本地代码完成，保证流程可复现。系统同时提供可选的受限策略接口：启用后，辅助模块只能从动作白名单中给出建议，且须经过预算约束与冠军-挑战者评估才能生效，不直接执行代码，也不改变评估口径；关闭时自动回退到规则策略。

端点配置支持公网强制 HTTPS、密钥环境变量白名单与 `allowed_hosts` 校验，密钥不写入配置、源码或实验产物。该分层设计使闭环在断网环境下仍能完整运行，同时为策略层的假设生成与参数自适应预留了扩展空间。

### 3.4 候选评估、上线与回滚

训练得到的候选模型不会直接覆盖当前模型。系统在同一评估口径下比较候选与当前版本，采用双门槛：近期提升须达到 `min_improvement`，历史守护集退化不得超过 `max_historical_drop`。两项同时满足才登记新版本，否则拒绝候选、保留冠军，并把被拒绝的假设一并入库。回滚时一并恢复特征、性能、诊断与策略四类监测状态快照，保证状态可恢复。

### 3.5 预算与实验追踪

运行配置限制更新次数、训练时间与 Token 数；标签按 `count_only` 模式记账，与批次释放时序解耦。`budget.min_updates=3` 对最少迭代次数做显式校验，不足时写 `min_updates_unmet` 事件并在摘要标记 `min_updates_met=false`，保证迭代次数真实可核查。每窗口产出一行 `decisions.jsonl`，记录「上线 / 不上线」判断、模型版本、判断理由、引用历史与候选增益，可作为按批次下发协议的对接点。

LocalTracker 保存 `events.jsonl`、`metrics.csv`、`summary.json`、`decisions.jsonl` 等本地证据；SwanLab 作为可选镜像通道，评测机无外网时自动切换为 `offline` 落盘，上传失败不中断闭环。提交目录内不含任何模型权重，平台侧后训练权重同样不随包分发。

### 3.6 策略层后训练

策略层另有一条可选的增强路径：把闭环产出的 1,381 条决策记录（`drift_diagnosis` 与 `update_decision` 按窗口配对还原请求体）作为监督微调集，在 PyTRiO 平台上以 `Qwen/Qwen3.8-27B` 为基座做 LoRA 续训（rank 32、学习率 1e-4、batch 2、每轮 100 步），三轮平均损失 7.396 → 3.663 → 3.008。第三轮权重经 30 条真实请求采样验证：输出 schema 合规 30/30，动作与规则门控判定一致 30/30。

该权重只作为策略层的可选调用目标：`llm.enabled` 默认关闭时回退规则门控，启用时仍须经预算约束与冠军-挑战者评估才能生效。训练在平台侧完成，评测机运行时保持全离线，闭环的评估口径与可复现性不因此改变。

## 4. 可复核产物

- `events.jsonl`：状态迁移、决策理由、候选结果与记录事件。
- `metrics.csv`：每窗口指标、动作与预算摘要。
- `summary.json`：运行状态、模型表现、运行配置、数据/模型哈希、`vs_official_baseline`、`min_updates_met` 等摘要。
- `decisions.jsonl`：逐批次上线/不上线判断链。
- `models/registry.json`：版本链元数据（**提交包内不含 `.joblib` 权重**）。
- `实验记录/离线复核包/`：158 条事件、6 条完整决策链、`复算.py` 一键复算。
- `实验记录/官方公开包CPU续训证据/`：A/B/C 三包各一份符合官方格式的 CPU 续训记录（不含权重）。

## 5. 后续工作

1. 打通标准 checkpoint 导出与按批次数据包协议，形成端到端评测链路。
2. 统一数据源适配层的清单解析格式，使不同格式的数据包走同一条编排链路。
3. 扩展策略层的阈值与冷却自适应、成本-增益帕累托分析，提升决策的自主性。
4. 补充总墙钟与进程 RSS 的运行时采集，支撑更细粒度的资源评估与跨领域数据验证。
