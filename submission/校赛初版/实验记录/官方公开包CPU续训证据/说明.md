# 官方公开包 CPU 续训证据

> 本目录收录 A / B / C 三个官方公开包按各自规格完成的 CPU 续训记录，只含训练报告，不含任何模型权重。赛题规定严禁将权重打包进提交包，三份 `checkpoint.npz` 均未随包分发；报告中的 `checkpoint_sha256` 与 `parent_checkpoint_sha256` 可用于逐字节核对。

## 1. 证据内容

三份报告均由各包随附的 `baselines/train.py` 生成，格式为 `contest.cpu-baseline-report.v1`。以本包 `checkpoint.npz` 为起点（`--from-baseline`），沿用原有权重、Adam 状态与标准化参数，仅用 `public/train.jsonl` 续训 2 个 epoch，`public/validation.jsonl` 只用于评估。

| 目录 | 任务 / 主指标 | 数据规模（训练 / 验证） | 累计 epoch | 公开验证集主指标 | CPU 事实 |
|---|---|---|---|---|---|
| `A包-round-1/` | 分类 / Macro-F1（越高越好） | 445 / 1,244 | 20 → 22 | **0.714030 → 0.716641** | `device: cpu`、1 线程、0.043 秒 |
| `B包-round-1/` | 回归 / RMSE（分钟，越低越好） | 7,032 / 1,679 | 15 → 17 | **681.159833 → 656.351785** | `device: cpu`、1 线程、0.040 秒 |
| `C包-round-1/` | 回归 / RMSE（cycles，越低越好） | 113,089 / 23,049 | 15 → 17 | **52.868573 → 52.740936** | `device: cpu`、1 线程、0.242 秒 |

每份目录含 `training.json`（输入哈希、参数量、累计步数、训练耗时、前后指标、父子 checkpoint 哈希）与 `history.jsonl`（逐 epoch 的 loss 与验证指标，含辅助指标 Accuracy / MAE）。运行栈为 numpy 2.5.4 / Python 3.13.7，无 GPU、无深度学习框架依赖。

## 2. 记录口径

1. 三份报告的 `validation_before` 与各包静态基线一致，该数值同时是续训起点，见第 3 节。
2. A 包为分类任务，主指标 Macro-F1 越高越好；B / C 为回归任务，主指标 RMSE 越低越好。B 包单位为分钟，C 包单位为 cycles，两者不互换比较。
3. 续训采用官方包 `--from-baseline` 语义：保留权重、Adam 矩、输入标准化与目标缩放，结果写入新的 run 目录，不覆盖随包基线 checkpoint；`parent_checkpoint_sha256` 指向各包原始 checkpoint。
4. 按批次下发的数据包、隐藏集与评分公式以组委会文档为准；本目录记录的是公开开发包上的本地训练结果。
5. 三次续训由官方包自带的训练脚本驱动；自研 Harness 闭环的迭代证据另见 `../离线复核包/`（6 条完整决策链 + 逐批 `deploy`/`no_update` 判断），两类证据分别对应官方包训练协议与自研闭环。

## 3. 官方公开包静态基线复现

| 包 | 公开验证集静态基线 | 验证样本数 |
|---|---|---:|
| A | Macro-F1 0.714030；Accuracy 0.878617 | 1,244 |
| B | RMSE 681.159833 分钟；MAE 563.105841 分钟 | 1,679 |
| C | RMSE 52.868573 cycles；MAE 38.899830 cycles | 23,049 |

三次运行用于复现三个公开包的静态基线，验证本地读取与评估链路；其数值与第 1 节三份报告的 `validation_before` 逐项一致。

## 4. 怎么核对

```bash
python -c "
import json, pathlib
root = pathlib.Path('实验记录/官方公开包CPU续训证据')
for p in sorted(root.rglob('training.json')):
    d = json.loads(p.read_text(encoding='utf-8'))
    print(p.parent.name, '| profile', d['profile'], '| device', d['device'], '| threads', d['cpu_threads_requested'])
    print('  parent ', d['parent_checkpoint_sha256'][:24])
    print('  before ', d['validation_before'])
    print('  after  ', d['validation_after'])
    print('  epochs ', d['initial_epochs'], '->', d['final_epochs'], '| secs', round(d['training_seconds'], 4))
"
```

如需核对权重本体，可在开发机对对应 `checkpoint.npz` 求 SHA-256，与 `training.json` 的 `checkpoint_sha256` 比对；权重按赛题要求不随提交包分发。历史曲线直接读同目录 `history.jsonl`，逐 epoch 的 loss 与 validation 与 `training.json` 的 `final_epochs` / `final_steps` 对齐。
