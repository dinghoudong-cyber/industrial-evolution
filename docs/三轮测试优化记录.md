# 四轮测试与优化记录

本记录严格按“测试 → 发现 → 修改 → 回归”顺序执行。所有数字来自实际运行；训练耗时会受到系统负载影响，因此性能结论同时参考 `cProfile` 中目标函数的累计耗时。

> 前三轮保留当时的历史数据，不代表当前最终版本。2026-10-31完成第四轮正确性、安全与交付修复后，当前基准和测试数量见文末“第四轮”。

## 第一轮：标准流程与漂移检测热点

### 测试目的

锁定18窗口标准演示的功能结果，并分析每个窗口都会执行的漂移检测热点。

### 优化前测试

- pytest：11项全部通过。
- 调优配置：18窗口、6次训练、2次上线、4次拒绝、0失败、平均指标`0.669028`、最后窗口`0.691223`、最终版本`v002`。
- `cProfile`总计：`3.578517秒`，`4,069,769`次函数调用。
- `FeatureDriftDetector.detect()`：18次累计`0.326秒`。
- SciPy `ks_2samp()`：144次累计`0.125秒`，但系统只使用KS统计量，不使用其P值。

使用的性能文件：

```text
runs\round1-before.prof
```

### 发现的问题

1. 每个特征、每个窗口都调用SciPy完整双样本KS检验。该函数除KS统计量外还计算比赛系统不需要的P值。
2. 不变的参考数组仍在每次窗口检测时重新筛选、排序并计算标准差。
3. 这部分占标准运行核心编排时间的明显比例，但不属于模型训练本身。

### 实施的优化

文件：`src/industrial_evolution/monitoring/feature_drift.py`

- 增加轻量ECDF差值实现，只计算KS统计量；
- 缓存参考特征的有限值排序结果和标准差；
- 只在参考分布更新后刷新缓存；
- 保留PSI、Wasserstein和所有漂移阈值不变。

新增测试：

- 快速KS结果与SciPy在普通值、重复值和NaN样本上逐项一致；
- 更新参考分布后缓存会刷新；
- 原漂移识别测试继续通过。

### 优化后测试

- pytest：13项全部通过。
- 调优配置结果完全不变：平均`0.669028`、最后窗口`0.691223`、6次训练、2次上线、4次拒绝、0失败、最终`v002`。
- `cProfile`总计：`3.266685秒`，`3,909,492`次函数调用。
- `FeatureDriftDetector.detect()`：从`0.326秒`下降到`0.099秒`，减少约`69.6%`。
- KS统计量计算：从SciPy完整检验的`0.125秒`下降到轻量实现的`0.012秒`，减少约`90.4%`。
- 整体profile时间减少约`8.7%`。整体数字包含Python和sklearn导入时间，因此仅作同机参考。

使用的性能文件：

```text
runs\round1-after.prof
```

### 未采用的方案

- 没有降低漂移检测频率，因为会改变响应时序；
- 没有近似KS或减少检测特征，因为可能改变诊断结果；
- 没有调整模型参数或阈值，因为第一轮目标是等价优化。

## 第二轮：120窗口压力与资源测试

### 测试目的

把标准18窗口扩展到120窗口，观察长时间运行中的累计耗时、峰值内存、日志完整性、回放容量和模型版本数量。

固定设置：初始600样本、每窗口200样本、渐进漂移从第30窗口开始、突发漂移从第75窗口开始、最多6次更新。

### 优化前测试

- 总耗时（包含`cProfile`和`tracemalloc`开销）：`12.205694秒`；
- 峰值跟踪内存：`2.644897 MiB`；
- `metrics.csv`：121行，即1行表头＋120窗口；
- `events.jsonl`：629条事件；
- 回放缓冲区：2400/2400，没有超过容量；
- 模型版本：3个，当前`v002`；
- 120窗口全部完成，0失败；
- 平均指标`0.658007`，最后窗口`0.541073`。

压力测试报告与profile：

```text
runs\round2-before.json
runs\round2-before.prof
```

### 发现的问题

长流profile中，PSI在960次特征检测里累计`1.256秒`。参考分布只有在模型成功上线后才更新，但系统每个窗口都重新：

1. 计算参考分位数；
2. 创建PSI分箱边界；
3. 统计参考直方图比例。

这些参考统计量在绝大多数窗口完全不变，属于可消除的重复计算。

### 实施的优化

文件：`src/industrial_evolution/monitoring/feature_drift.py`

- 将PSI分箱边界和参考直方图比例加入参考统计缓存；
- 每个窗口只计算当前数据的直方图比例；
- 仅在初始化和`update_reference()`后重建缓存；
- 公开的`population_stability_index()`保持原算法，便于独立验证；
- 新增缓存PSI与原函数结果一致的测试。

### 优化后测试

- 总耗时：`11.204867秒`，减少约`8.2%`；
- 峰值跟踪内存：`2.637312 MiB`，没有因缓存产生可见增长；
- `FeatureDriftDetector.detect()`：从`1.935秒`下降到`0.964秒`，减少约`50.2%`；
- PSI路径：从`1.256秒`下降到`0.315秒`，减少约`74.9%`；
- 函数调用：从`2,253,977`下降到`2,112,064`；
- 结果逐项一致：120窗口、6次训练、2次上线、4次拒绝、0失败、平均`0.658007`、最后窗口`0.541073`、最终`v002`；
- `metrics.csv`仍为121行，事件仍为629条，回放容量仍为2400。

压力测试报告与profile：

```text
runs\round2-after.json
runs\round2-after.prof
```

### 未采用的方案

- 没有减少PSI检测窗口，因为会改变漂移响应；
- 没有增大日志缓冲批量写入，因为突然退出时可能丢失更多诊断事件；
- 没有修改回放采样算法。压力测试中缓冲区容量稳定，且其耗时不是主要热点；
- 没有压缩模型文件。当前仅3个版本，压缩会增加训练阶段CPU开销。

## 第三轮：异常输入与用户操作

### 测试目的

从普通用户角度验证缺失文件、目标列错误、非数值特征和数据不足时的提示，同时复测预算、镜像故障隔离和自动回滚。

### 优化前测试

实际执行了以下错误输入：

- CSV文件不存在；
- 目标列不存在；
- 特征中包含字符串列；
- `initial-size`大于CSV总行数。

四种情况都会输出完整Python调用栈。非数值特征直到`orchestrator.run()`读取初始数据时才被发现，此时本地运行记录器已经创建，存在留下不完整运行目录的风险。`_xy()`还会在每个窗口重复检查整组特征类型。

### 发现的问题

1. 已知的用户输入错误以开发者堆栈呈现，真正原因被埋在最后一行；
2. 参数和数据结构验证分散在构造、初始数据读取和每个窗口转换阶段；
3. 非数值特征验证过晚；
4. 特征列清单每个窗口重复构造；
5. `initial-size=1`和过小窗口没有在数据流创建阶段明确拒绝。

### 实施的优化

文件：

- `src/industrial_evolution/data/stream.py`
- `src/industrial_evolution/cli.py`
- `tests/test_cli.py`

改动：

- 在读取和启动运行记录器前验证文件存在、初始样本数、窗口大小、目标列、删除列、空特征和非数值特征；
- 特征列验证一次后缓存，窗口转换不再重复扫描数据类型；
- 已知的路径、编码、配置和输入值错误通过Argparse输出简洁错误并返回状态码2；
- 核心训练和其他未知异常不在该边界捕获，仍保留完整诊断，避免掩盖程序缺陷；
- 新增4组子进程级CLI测试，确认无`Traceback`且不会创建输出目录。

### 优化后测试

错误输入现在只输出命令用法和一条原因，例如：

```text
usage: cli.py [-h] {demo,run-csv} ...
cli.py: error: CSV 文件不存在：D:\industrial_evolution\missing.csv
```

Git Bash中的中文可能因终端编码显示异常，但不再出现Python堆栈；项目批处理脚本已设置UTF-8代码页。

最终回归：

- pytest：17项全部通过；
- 调优配置：18窗口、6次训练、2次上线、4次拒绝、0失败、平均`0.669028`、最后窗口`0.691223`、最终`v002`；
- 静态配置：18窗口、0次更新、0失败、平均`0.614526`、最后窗口`0.538245`、最终`v000`；
- 自动回滚测试通过；
- 可选镜像故障隔离测试通过；
- 预算硬限制测试通过；
- 三种CSV内容错误和缺失文件测试均返回状态码2且无堆栈。

最终演示目录：

```text
runs\run-20261029-074753-7aa3dc  # 调优配置
runs\run-20261029-074802-d91e38  # 静态基线
```

### 未采用的方案

- 没有捕获`_run()`中的所有`Exception`，因为这会把真实训练或编程错误伪装成输入错误；
- 没有自动编码字符串特征。编码方式取决于官方数据语义，当前明确提示用户处理更安全；
- 没有自动缩小`initial-size`或窗口大小，因为静默修改参数会破坏实验可复现性；
- 没有把错误信息全部改成英文。项目面向中文用户，终端编码应由运行环境解决。

## 第四轮：正确性、安全与正式交付准备（2026-10-31）

### 测试目的

根据赛题PDF重新审查标签成本、验证隔离、预算、版本追踪、回滚、异常输入、离线安全和容器交付，而不只验证合成流能否跑通。

### 修复前确认的问题

1. 18窗口实际访问600条初始标签和3600条流式标签，但账本只记录1320条训练标签；
2. 初始验证集被放入回放池，训练回放和历史守护集每次重叠10—17条；
3. 初始训练可在`max_labels=0`和极小训练时间上限下直接突破预算；
4. 上线窗口把旧模型分数写在新模型版本名下，末窗口上线时总结也会错配；
5. 回滚只恢复模型，没有恢复特征、标签、性能和策略状态；
6. 全NaN和全Inf窗口被错误判为“无漂移”；
7. 字符串分类标签导致初始化崩溃，坏YAML和零窗口数据处理不完整；
8. Windows默认代码页下4项CLI测试因强制UTF-8解码失败；
9. 项目声明Python 3.10，但使用Python 3.11的`StrEnum`；
10. DeepSeek配置可同时选择任意环境变量和任意目标URL；
11. 缺少`.dockerignore`、依赖锁和Docker/Ruff使用说明。

### 实施的修复

- 标签按稳定样本ID首次访问计费，评分、验证和训练共用去重账本；
- 初始验证/守护集不再进入回放池，候选训练前断言与守护集交集为0；
- 初始训练、候选训练和Token增加预算检查与违规记录，失败训练也记录耗时；
- 每个窗口分别记录`scored_model_version`和`deployed_model_version`；
- 总结分别记录`final_score_model_version`和`final_deployed_model_version`；
- 回滚同时恢复模型、特征参考、标签分布、性能检测器和策略状态；
- 漂移检测增加有限值比例和非有限值比例变化，全NaN/Inf返回数据质量失败；
- CSV采用分块预检和分块窗口拼装，支持字符串/多分类目标并拒绝零完整窗口；
- 标签漂移从二分类均值差改为完整类别分布总变差；
- CLI区分输入错误、部分容错和整体失败，异常窗口不再计为`no_update`；
- Windows子进程测试显式固定UTF-8环境；
- `StrEnum`替换为Python 3.10兼容枚举；
- DeepSeek配置固定官方HTTPS地址和`DEEPSEEK_API_KEY`；
- 安装Ruff 0.14.14，新增依赖锁、`.dockerignore`和Docker使用说明。
