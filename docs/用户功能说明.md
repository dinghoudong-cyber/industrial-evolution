# 工业模型自进化系统：用户功能说明

## 1. 这套系统是做什么的

工业模型上线后，设备工况、原材料、环境和传感器状态会持续变化。原来准确的模型可能逐渐出现误报、漏报或预测偏差。本系统用于在连续数据流中自动完成以下闭环：

```text
接收新数据 → 使用当前模型预测 → 检测漂移 → 判断是否需要更新
           → 训练候选模型 → 安全评估 → 上线或拒绝 → 必要时回滚
```

系统的目标不是频繁训练，而是在性能、训练时间、标注数量和大模型 Token 预算之间做受控决策。第一版已经用合成工业数据验证完整流程，后续可替换为官方数据适配器。

### 适合哪些用户

- 需要参加“工业模型自进化”类比赛的学生团队；
- 需要演示持续学习、漂移检测和模型回滚流程的开发者；
- 希望在接入真实数据前先验证工程闭环的算法人员；
- 需要查看模型为什么更新、为什么拒绝上线的实验管理人员。

### 当前能力边界

- 内置演示是二分类任务，同时预留回归模型接口；
- CSV 接口只接受数值特征，分类目标允许离散数值或字符串类别；
- 标签按样本首次被评分、验证或训练访问时计费，同一样本不重复计费；
- PyTRiO、官方评测 SDK 和正式评分公式尚未发布，因此目前没有进行真实平台对接；
- SwanLab 是可选功能，未安装或不可用不会阻断本地运行；
- 当前不允许智能体自由生成和执行代码。

## 2. 最快的使用方式

### 方法一：双击运行

打开：

```text
D:\industrial_evolution
```

双击：

```text
运行演示.bat
```

程序会自动使用 `configs\tuned.yaml`，依次运行稳定、渐进漂移和突发漂移三个阶段。完成后，结果保存在：

```text
D:\industrial_evolution\runs\run-日期时间-编号
```

### 方法二：命令行运行

在 PowerShell 中执行：

```powershell
cd D:\industrial_evolution
.\.venv\Scripts\python.exe -m industrial_evolution.cli demo `
  --config configs\tuned.yaml
```

指定其他结果目录：

```powershell
.\.venv\Scripts\python.exe -m industrial_evolution.cli demo `
  --config configs\tuned.yaml `
  --output D:\industrial_evolution\my-runs
```

## 3. 一次运行中会发生什么

### 第一步：训练初始模型

系统将初始数据按原始顺序划分为训练部分和验证部分，训练第一个 champion 模型。这个模型是后续所有候选模型的比较基准。

系统记录：

- 初始训练样本数；
- 验证样本数；
- 初始模型指标；
- CPU 训练时间；
- 初始模型版本，如 `v000`。

### 第二步：按窗口接收数据

新数据不会一次性全部交给模型，而是按时间顺序划分为窗口。每个窗口严格执行“先预测、后更新”，防止未来数据泄漏。

### 第三步：监测漂移

系统会同时观察三类变化。

#### 输入特征漂移

使用以下指标比较当前窗口和参考数据：

- PSI：观察特征分布比例变化；
- KS：观察两个分布的最大差异；
- Wasserstein 距离：观察分布移动的距离。

系统还会给出漂移最明显的前三个特征，例如：

```text
sensor_00, sensor_02, sensor_01
```

#### 性能漂移

系统持续观察滚动平衡准确率是否低于基准，并使用 Page-Hinkley 检测连续性能变化。

#### 标签分布漂移

分类任务中，系统比较当前窗口与参考数据的完整类别分布，使用总变差距离识别类别变化，因此不再局限于数值0/1二分类标签。

### 第四步：诊断漂移类型

系统会输出以下诊断之一：

| 漂移类型 | 含义 |
|---|---|
| `none` | 没有达到阈值的明显漂移 |
| `covariate` | 输入特征分布变化，但性能未明显下降 |
| `label` | 完整类别分布出现明显变化 |
| `concept_suspected` | 输入可能相似，但模型性能已经下降 |
| `mixed` | 同时出现输入、标签或性能变化 |

### 第五步：决定是否训练

即使检测到漂移，系统也不会马上训练。它会继续检查：

- 漂移是否连续出现；
- 是否仍处于更新冷却期；
- 更新次数是否用尽；
- 训练时间预算是否用尽；
- 标注预算是否足够；
- Token 预算是否足够。

可能的动作：

| 动作 | 含义 |
|---|---|
| `no_update` | 保持当前模型，不消耗更新预算 |
| `retrain_with_replay` | 使用近期数据和历史回放数据训练候选模型 |
| `rollback` | 新模型连续退化，恢复上一稳定版本 |

### 第六步：训练候选模型

训练数据由两部分组成：

1. 当前窗口中较新的训练样本；
2. 回放缓冲区中的历史代表样本。

这样既能适应新工况，也能降低模型遗忘旧工况的风险。缓冲区有容量上限，分类任务会尽量保留各类别样本。

### 第七步：候选模型安全评估

新模型不会训练完就直接上线。系统会同时比较：

- 当前窗口留出集上的提升；
- 历史守护集上的退化；
- 是否达到最小上线收益；
- 是否超过允许的历史性能下降。

只有同时满足条件，challenger 才会替换 champion。否则系统记录拒绝原因并继续使用原模型。

常见拒绝原因：

```text
近期提升未达到门槛
历史守护集退化超过上限
训练预算不允许
```

### 第八步：持续观察和自动回滚

新模型上线后，系统继续观察后续窗口。如果性能连续低于上线基准并超过回滚阈值，系统会：

1. 停止使用当前模型；
2. 从模型注册表找到上一稳定版本；
3. 加载旧模型；
4. 同时恢复性能基线、特征参考分布、标签参考分布和策略状态；
5. 继续处理后续数据。

回滚不会删除失败模型，方便事后复盘。

## 4. 系统提供的主要功能

| 功能 | 输入 | 输出 | 用户价值 |
|---|---|---|---|
| 合成漂移演示 | YAML 配置 | 18个数据窗口 | 无需官方数据即可展示完整流程 |
| CSV 顺序流 | 数值 CSV、目标列 | 按时间顺序的数据窗口 | 快速接入自己的表格数据 |
| 多指标漂移检测 | 参考数据、当前窗口 | 漂移分数、重点特征 | 避免只用单一指标误判 |
| 更新决策 | 漂移报告、冷却期、预算 | 更新或不更新 | 避免无效训练和预算浪费 |
| 回放训练 | 近期样本、历史样本 | 候选模型 | 兼顾新工况和旧工况 |
| 安全上线 | 候选模型、近期和历史守护集 | 上线或拒绝 | 防止只在新数据上表现好的模型误上线 |
| 模型注册 | 模型及元数据 | `v000`、`v001` 等版本 | 支持追踪、加载和回滚 |
| 自动回滚 | 连续性能退化 | 上一稳定模型 | 保证系统始终有可用模型 |
| 成本账本 | 训练、标签、Token 使用量 | 剩余预算和消耗 | 对应比赛成本收益要求 |
| 实验记录 | 每个窗口的事件和指标 | CSV、JSONL、JSON | 支持复现、报告和答辩 |
| SwanLab 镜像 | 本地记录事件 | 云端实验指标 | 云端不可用时仍保留本地结果 |
| 安全兜底 | 运行时异常 | 最后稳定模型 | 单个窗口失败不导致整个流程中断 |

## 5. 四套配置怎么选择

配置文件位于：

```text
D:\industrial_evolution\configs
```

### `tuned.yaml`

适合直接演示。它针对当前合成漂移流调优，漂移响应更快。

### `default.yaml`

较保守的通用起点，需要更多连续证据才更新。接入新数据时可以先从这里开始，再通过对照实验调整。

### `static.yaml`

禁止任何模型更新，用作静态基线。它用于回答“自进化系统是否真的比部署后不再更新更好”。

### `deepseek-dev.yaml`

仅用于DeepSeek开发验证。它沿用调优后的漂移和训练参数，并开启受Token、调用次数和置信度限制的混合策略。API不可用时自动退回规则策略，不应直接用于正式离线比赛镜像。

### `local-qwen.yaml`

面向断网评测环境的配置：`provider: openai_compatible`，端点指向本机的 vLLM / sglang 服务（默认 `http://127.0.0.1:8000/v1`），`api_key_required: false` 表示本地服务不校验鉴权。用 `llm-smoke-test` 和 `env-check` 验证后再跑正式数据流，详见 [README 的策略模型接入](../README.md#策略模型接入)。

### 关键参数

| 配置项 | 作用 | 调大后的典型影响 |
|---|---|---|
| `psi_threshold` | PSI 漂移阈值 | 减少输入漂移告警 |
| `ks_threshold` | KS 漂移阈值 | 减少分布差异告警 |
| `performance_drop_threshold` | 性能下降阈值 | 只有更明显退化才告警 |
| `consecutive_windows` | 连续确认窗口数 | 降低误触发，但响应更慢 |
| `cooldown_windows` | 更新后的等待窗口数 | 减少重复训练 |
| `recent_fraction` | 近期数据在训练中的比例 | 更快适应新分布，但可能遗忘历史 |
| `min_improvement` | 上线所需最低提升 | 上线更谨慎 |
| `max_historical_drop` | 允许的历史退化 | 更容易拒绝遗忘旧工况的模型 |
| `rollback_drop` | 回滚性能差值 | 数值越大，越不容易回滚 |
| `max_updates` | 最大更新尝试次数 | 允许更多训练成本 |
| `max_labels` | 最大首次访问标签数 | 允许评分、验证和训练访问更多不同样本标签 |

调整参数时应始终与静态基线做对照，不要只看一次运行的最高分。

## 6. 如何接入自己的 CSV

### 官方数据包

如果拿到的是赛题数据包（带初始训练集与评测流两组文件），不要手工拼 CSV，直接用：

```powershell
python -m industrial_evolution.cli run-official --pack D:\官方数据包 --print-spec
python -m industrial_evolution.cli run-official --pack D:\官方数据包 --config configs\official.yaml
```

清单字段、可覆盖的参数、以及哪几类数据问题会被提前拦住，见
[官方数据包接入说明](官方数据包接入说明.md)。

### 数据要求

- 第一行是列名；
- 每一行代表一个按时间到达的样本；
- 行顺序必须保持真实时间顺序；
- 目标列必须存在且不能包含缺失值；
- 分类目标允许离散数字或字符串类别；回归目标必须是有限数值；
- 数值特征可以包含缺失值，但不能包含正负无穷；
- 初始数据之后必须至少能组成一个完整窗口；
- 时间戳、编号等不应直接训练的列可以删除。

示例：

```csv
timestamp,sensor_01,sensor_02,sensor_03,label
2026-01-01 08:00,0.81,12.4,3.2,0
2026-01-01 08:01,0.86,12.7,3.4,1
```

运行：

```powershell
cd D:\industrial_evolution
.\.venv\Scripts\python.exe -m industrial_evolution.cli run-csv `
  --csv D:\数据\train.csv `
  --target label `
  --initial-size 1000 `
  --window-size 200 `
  --drop-column timestamp
```

参数含义：

- `--csv`：CSV 文件位置；
- `--target`：目标列名称；
- `--initial-size`：最前面的多少行用于初始模型；
- `--window-size`：后续每个流式窗口包含多少行；
- `--drop-column`：不参与训练的列，可以重复指定；
- `--config`：使用哪套 YAML 配置；
- `--output`：结果保存目录。

## 7. 如何查看运行结果

每次运行都会创建独立目录：

```text
runs\run-日期时间-编号\
├── events.jsonl
├── metrics.csv
├── summary.json
└── models\
    ├── registry.json
    ├── v000.joblib
    └── v001.joblib
```

### `summary.json`

适合快速查看整次运行结果，主要字段包括：

| 字段 | 含义 |
|---|---|
| `windows_processed` | 已处理窗口数 |
| `successful_windows` | 成功完成评分与诊断的窗口数 |
| `run_status` | `complete`、`partial` 或 `failed` |
| `updates_attempted` | 候选训练次数 |
| `updates_deployed` | 成功上线次数 |
| `updates_rejected` | 被安全拒绝次数 |
| `rollbacks` | 自动回滚次数 |
| `failures` | 进入安全兜底的窗口数 |
| `initial_score` | 初始模型验证指标 |
| `mean_score` | 所有流式窗口的平均指标 |
| `final_score` | 最后一个成功窗口在更新前的在线指标 |
| `final_score_model_version` | 与 `final_score` 严格对应的模型版本 |
| `final_deployed_model_version` | 运行结束时实际部署版本，可能刚上线而尚未经过未来窗口评估 |
| `budget` | 训练、首次标签访问和 Token 使用情况 |

### `metrics.csv`

每一行对应一个数据窗口，适合使用 Excel、Pandas 或实验分析脚本查看。

重点列：

- `score`：当前 champion 在本窗口上的指标；
- `drift_kind`：漂移诊断类型；
- `feature_drift_score`：输入漂移强度；
- `performance_drop`：相对性能基准的下降；
- `action`：系统决定执行的动作；
- `status`：候选是否上线、拒绝或回滚；
- `candidate_improvement`：候选相对 champion 的近期提升；
- `training_seconds_used`：累计训练时间；
- `labels_used`：累计首次访问的不同样本标签数。

### `events.jsonl`

这是最完整的事件流水，每一行是一条 JSON 事件。它用于回答：

- 系统什么时候发现了漂移；
- 为什么决定训练；
- 候选模型为什么被拒绝；
- 哪个模型在什么窗口上线；
- 是否发生异常或自动回滚。

### `models\registry.json`

记录所有模型版本、当前 champion 和每个版本的训练来源。模型文件使用 Joblib 保存。

## 8. 安全与成本控制

### 硬预算

更新前会检查：

- 最大更新次数；
- 最大累计训练秒数；
- 最大标签使用量；
- 最大 Token 使用量。

预算不足时系统保留当前模型，不会先训练再发现超支。

### 更新冷却期

模型训练后会等待若干窗口，避免同一段漂移触发连续训练。

### Champion-Challenger

候选模型必须同时通过近期数据和历史守护集评估。训练成功不等于允许上线。

### 原子化模型记录

模型文件和注册表使用先写临时文件、再替换的方式，降低写入中断造成文件损坏的风险。

### 可选服务隔离

SwanLab 等镜像记录器失败时，系统会记录降级事件并继续本地运行，不让可选服务中断核心闭环。

### 最后稳定模型兜底

单个窗口发生异常时，系统保留最后稳定 champion，记录错误后继续运行。

## 9. 当前演示结果

固定随机种子为 `42`，相同18个窗口上的结果：

| 方案 | 平均平衡准确率 | 最后窗口指标 | 更新尝试 | 成功上线 | 异常 |
|---|---:|---:|---:|---:|---:|
| 静态基线 | 0.614526 | 0.538245 | 0 | 0 | 0 |
| 自进化系统（无泄漏守护集） | 0.676200 | 0.699060 | 6 | 4 | 0 |

移除训练/守护集重叠后，自进化配置的平均指标绝对提升 `0.061674`，最后窗口提升 `0.160815`。标准运行按首次访问计入4200个不同标签。相同种子复跑后，关键指标、动作序列和模型版本一致；训练耗时会有正常的小幅波动。

这些数字只证明当前闭环在合成数据上有效，不能代表官方隐藏测试成绩。

## 10. 常见问题

### 双击脚本后提示找不到虚拟环境

确认以下文件存在：

```text
D:\industrial_evolution\.venv\Scripts\python.exe
```

如果不存在，需要先按照 README 安装依赖。

### 运行后没有发生模型更新

这不一定是故障。常见原因：

- 漂移没有达到阈值；
- 尚未满足连续确认窗口数；
- 系统处于冷却期；
- 候选模型提升不足；
- 历史守护集退化过大；
- 更新、标注或训练时间预算已经耗尽。

查看 `metrics.csv` 的 `reason` 列和 `events.jsonl` 可以确认原因。

### CSV 提示目标列不存在

检查 `--target` 后的名称是否与 CSV 第一行完全一致，包括大小写和空格。

### CSV 提示只接受数值特征

使用 `--drop-column` 删除时间戳、字符串编号等列。类别特征需要在接入前编码为数值，或者后续扩展数据适配器。

### SwanLab 不可用

默认配置关闭 SwanLab，不影响本地记录。即使开启后连接失败，本地实验仍会继续，并在事件日志中留下 `tracker_mirror_failure` 或 `swanlab_disabled`。

### 命令行中文显示乱码

这是终端编码显示问题，不代表程序运行失败。结果文件统一使用 UTF-8；`metrics.csv` 首行带 UTF-8 BOM，便于 Excel 正确识别中文。

### 为什么最后窗口分数不等于新模型上线评估分数

系统遵守“先预测、后训练”。`final_score` 表示最后一个窗口到达时，更新前 champion 的真实流式表现；候选模型在该窗口后半部分的验证分数单独记录在候选评估事件中。

## 11. 官方数据发布后的接入步骤

1. 阅读官方数据字段、标签可见规则和评测 SDK；
2. 新增官方 `StreamSource` 适配器；
3. 替换为官方主指标和成本公式；
4. 明确初始训练、在线评估和标注分别如何计费；
5. 使用公开训练集构建 walk-forward 对照实验；
6. 重新校准漂移、上线和回滚阈值；
7. 接入 PyTRiO 模型服务和受约束策略智能体；
8. 在离线、限时、限内存条件下重复运行镜像；
9. 将所有实验同步到正式 SwanLab 项目；
10. 使用隐藏测试前冻结代码、依赖和配置版本。

在官方规则明确前，不应把合成数据的最佳参数直接用于正式评测。

## 12. 策略大模型接入（开发用 DeepSeek / 评测用本地 Qwen）

策略模型有两种接法，决策逻辑、白名单校验、预算与回退路径完全一致，只换 `provider` 和端点：

- `provider: deepseek`：官方端点，联网开发调试用；
- `provider: openai_compatible`：本地 vLLM / sglang 承载的 Qwen，断网评测用（见 `configs/local-qwen.yaml`）。

端点写错、公网用 http、或密钥环境变量名不合规时，程序启动就会报错，不会静默降级。

### 它负责什么

大模型只在规则策略已经确认“漂移成立、冷却结束、训练预算允许”后参与二次判断。它只能返回：

```text
no_update
retrain_with_replay
```

自动回滚、候选评估、预算和模型上线仍由确定性代码控制。

### 它不能做什么

- 不能执行Python、终端或系统命令；
- 不能读取或修改项目文件；
- 不能直接训练或上线模型；
- 不能绕过预算、冷却期和历史守护集；
- 不能阻止安全回滚；
- 不能获得原始工业样本或API密钥。

### 安全设置密钥

在DeepSeek官方平台创建密钥后，将其保存为Windows用户环境变量或PyCharm运行配置：

```text
DEEPSEEK_API_KEY
```

不要把密钥写入：

```text
configs\deepseek-dev.yaml
源代码
README
聊天记录
Git提交
```

设置环境变量后需要重新启动终端、PyCharm或Claude Code，使新进程读取到它。

### 安装可选依赖

```powershell
cd D:\industrial_evolution
.\.venv\Scripts\python.exe -m pip install -e ".[deepseek]"
```

### 配置文件

```text
configs\deepseek-dev.yaml
```

主要限制：

| 配置 | 当前值 | 作用 |
|---|---:|---|
| 模型 | `deepseek-flash` | 开发阶段策略模型 |
| 总Token预算 | 5000 | 超过后不再调用 |
| 单次预留预算 | 800 | 剩余不足时不调用 |
| 最大调用次数 | 6 | 防止无限调用 |
| 最大输出 | 160 Token | 限制JSON长度 |
| 最小置信度 | 0.65 | 低于门槛退回规则 |
| 调用冷却 | 2窗口 | 否决后短期不重复请求 |

### 真实连通测试

以下命令会产生一次真实API调用和费用：

```powershell
.\.venv\Scripts\python.exe -m industrial_evolution.cli llm-smoke-test `
  --config configs\deepseek-dev.yaml
```

返回内容包括模型、动作、置信度、实际Token和延迟，不显示密钥。

### 完整开发演示

```powershell
.\.venv\Scripts\python.exe -m industrial_evolution.cli demo `
  --config configs\deepseek-dev.yaml
```

如果密钥缺失、网络失败、API限流、输出非法或置信度不足，系统会记录 `llm_fallback` 并使用原规则策略继续运行。

摘要中的统计含义：

- `llm_attempts`：进入提供商调用分支的次数；
- `llm_calls`：成功取得并解析模型响应的次数；
- `llm_fallbacks`：最终退回规则策略的次数；
- `budget.tokens_used`：API返回的实际累计Token。

DeepSeek仅用于开发调试，不作为最终 Harness。正式 Harness 使用赛方建议的 Qwen3.8 27B 或 4B；如有需要，可选择基于 Qwen 使用 PyTRiO 后训练。模型 ID 和 API Key 按平台要求通过安全渠道提交，不写入源码、配置或实验记录。
