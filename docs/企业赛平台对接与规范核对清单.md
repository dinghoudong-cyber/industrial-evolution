# 企业赛平台对接与规范核对清单

> **阶段边界（2026-11-12 确认）**：当前是**校赛**阶段。赛题规则说明 Qwen3.8 27B 模型服务与 PyTRiO 后训练能力在**进入企业赛阶段后**才提供（同时发放 500 元 PyArrow 平台代金券）。因此校赛提交**不接入、不声明、不估填**任何平台模型调用；本清单用于校赛材料里如实标注「下一阶段待办」，并在资格确认后按表逐项落地。

## 1. 平台侧信息与额度（企业赛资格通过后第一时间办理）

| # | 事项 | 需要取得的官方信息 | 落地动作 | 验收标准 |

> 严禁事项（赛题原文口径）：不联网搜索、不调用其他外部模型 API、不打包任何模型权重进提交包（≤2 GiB）、不使用 Embedding 模型（无 GPU）。`requirements.lock` 与镜像层扫描已确认无相关依赖。

## 3. B 包批次下发协议（校赛未适配，企业赛必须补）

赛题规则：B 包按批次下发，**必须先输出当前批次模型或不上线的判断，才能获取下一批数据**；评测时总能拿到标签，且无需消耗配额申请。

| 缺口 | 现状 | 待办 |
|---|---|---|
| 逐批 `deploy/no_update` 判断输出 | 已补 `decisions.jsonl` 逐窗口落盘（校赛版） | 改为评测方规定的 stdout/文件协议与字段名 |
| 「判断后才取下一批」握手 | 当前 `StreamSource` 是拉模式迭代器，一次性离线切窗 | 增加阻塞式批次流：`emit decision → await next batch`，含超时与不上线分支 |
| 标签可见性 | 项目曾把标签当配额，超限整窗跳过（`budget_skipped`） | 已改为默认 `count_only`（只记账不阻断）；`enforce` 模式保留供本地模拟。企业赛按平台标签释放时序再校准 |
| 最终模型交付 | 闭环产 sklearn `joblib`；官方协议要 `checkpoint.npz + training.json + history.jsonl` | 打通「闭环 → 官方格式 checkpoint」的导出，并接入 `vs_official_baseline` |
| 多任务主指标 | A 分类 / B、C 回归 | 已支持可配置主指标（macro_f1 / negative_rmse）；C 的 NASA 非对称分待官方公式 |

## 5. 校赛提交时如何表述这一段

- 写「平台模型服务在企业赛阶段提供，校赛阶段未接入」，**不写**「已接入 Qwen3.8」或「已完成 PyTRiO 后训练」。
- 写「正式平台入口、批次下发协议、标签释放时序、评分公式以组委会文档为准」，**不写**「已适配正式评测接口」。
- 本清单可作为「已识别并规划」的证据，但不能替代实际接入验证；所有未发生事项一律标注「未发生」。
