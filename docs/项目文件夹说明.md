# 工业模型自进化系统：项目文件夹详细说明

本文说明 `D:\industrial_evolution` 中每一个主要文件夹的用途、包含内容、数据流向、是否需要人工修改，以及正式提交时是否应保留。

## 一、完整目录结构

```text
D:\industrial_evolution\
├── .venv\                         # 本项目独立Python运行环境
├── .pytest_cache\                 # pytest自动生成的测试缓存
├── configs\                       # 系统运行配置
├── dist\                          # docker save 导出的离线镜像包
├── docker-runs\                   # 容器验证时的挂载目录
├── docs\                          # 用户、开发和测试文档
├── runs\                          # 每次运行产生的实验结果
├── src\                           # 正式源代码
│   ├── industrial_evolution\      # 核心Python程序包
│   │   ├── data\                  # 数据流和数据验证
│   │   ├── evaluation\            # 候选模型上线评估
│   │   ├── llm\                   # DeepSeek提供商与严格响应结构
│   │   ├── memory\                # 历史回放缓冲区
│   │   ├── models\                # 模型适配和版本注册
│   │   ├── monitoring\            # 漂移检测与归因
│   │   ├── policy\                # 更新决策策略
│   │   ├── tracking\              # 本地与云端实验记录
│   │   └── training\              # 候选模型训练
│   └── industrial_evolution.egg-info\ # 安装工具自动生成的包信息
├── tests\                         # 自动化测试
└── tools\                         # 开发辅助脚本（mock端点、文档渲染）
```

运行Python后，部分目录下还会出现：

```text
__pycache__\                       # Python字节码缓存
```

这些缓存目录不是业务代码。

# 二、项目根目录 `D:\industrial_evolution`

## 主要作用

这是整个项目的根目录。所有代码、配置、文档、测试和运行结果都从这里组织。

用户通常在这个目录中执行：

```powershell
.\.venv\Scripts\python.exe -m industrial_evolution.cli demo `
  --config configs\tuned.yaml
```

## 根目录中的重要文件

| 文件 | 功能 | 是否应修改 |
|---|---|---|
| `README.md` | 项目总入口，提供快速启动、目录结构和开发验证说明 | 可以维护 |
| `pyproject.toml` | 项目名称、Python版本、依赖、命令入口、pytest和Ruff配置 | 增加依赖时修改 |
| `Dockerfile` | 使用锁定依赖构建正式离线系统镜像 | 接入官方环境后需要复测 |
| `requirements.lock` | Docker生产环境的精确依赖版本 | 依赖升级并通过全量测试后更新 |
| `.dockerignore` | 排除虚拟环境、运行结果、密钥和缓存，缩小构建上下文 | 新增本地产物时维护 |
| `运行演示.bat` | Windows双击运行入口 | 一般不需要修改 |
| `.gitignore` | 指定Git不应提交的虚拟环境、缓存和运行结果 | 新增生成目录时修改 |

## 数据流向

```text
configs配置
   ↓
src正式代码
   ↓
runs运行结果
   ↓
docs报告、说明和复盘
```

# 三、`.venv`：项目虚拟环境

完整路径：

```text
D:\industrial_evolution\.venv
```

## 主要作用

`.venv`保存该项目专用的Python解释器和依赖，避免与电脑上的其他Python项目互相影响。

当前环境包含：

- NumPy；
- Pandas；
- SciPy；
- scikit-learn；
- Joblib；
- Pydantic；
- PyYAML；
- pytest；
- Ruff；
- OpenAI Python SDK（可选，仅用于DeepSeek官方兼容API）；
- 项目自身的可编辑安装信息。

## 重要子目录

### `.venv\Scripts`

Windows可执行程序入口。

| 文件 | 作用 |
|---|---|
| `python.exe` | 本项目实际使用的Python解释器 |
| `pip.exe` | 安装项目依赖 |
| `pytest.exe` | 执行自动化测试 |
| `Activate.ps1` | 在PowerShell中激活虚拟环境 |
| `activate.bat` | 在cmd中激活虚拟环境 |

项目命令优先使用：

```text
D:\industrial_evolution\.venv\Scripts\python.exe
```

这样不会误用其他Python版本。

### `.venv\Lib\site-packages`

保存第三方Python库的实际代码，例如Pandas和scikit-learn。

## 是否需要人工修改

不要手动修改 `.venv` 中的任何Python文件。依赖变化应修改 `pyproject.toml`，再通过pip安装。

## 正式提交时是否保留

通常不把本地 `.venv` 直接放进Docker镜像或提交压缩包。Docker根据 `requirements.lock` 安装精确生产依赖，再以 `--no-deps` 安装项目源码。

如果 `.venv` 损坏，可以删除后重新创建，不会损失项目源代码。

# 四、`.pytest_cache`：测试缓存

完整路径：

```text
D:\industrial_evolution\.pytest_cache
```

## 主要作用

pytest自动记录：

- 上次失败的测试；
- 测试节点编号；
- 测试运行缓存。

它可以加快重复测试或支持“只重跑失败测试”。

不需要。这个目录完全由pytest管理。

## 是否可以删除

可以安全删除。下次运行pytest时会自动重新创建。

## 正式提交时是否保留

不保留，也不应进入Docker镜像。

# 五、`configs`：系统配置中心

完整路径：

```text
D:\industrial_evolution\configs
```

## 主要作用

保存系统运行参数，把算法阈值、预算和数据流规模从代码中分离出来。这样调整实验时不需要修改Python代码。

## 当前文件

### `configs\tuned.yaml`

针对当前合成漂移数据调优的演示配置。

适合：

- 双击演示；
- 展示系统会自动更新；
- 验证上线和拒绝逻辑；
- 与静态基线比较。

### `configs\default.yaml`

较保守的通用起点。

适合：

- 接入一套新的工业数据；
- 在没有完成参数实验前作为初始配置；
- 降低过早更新的概率。

### `configs\static.yaml`

静态对照配置，将最大更新次数设为0。

适合：

- 建立组委会要求的静态基线；
- 证明自进化系统是否真正有效；
- 计算更新带来的净收益。

### `configs\deepseek-dev.yaml`

DeepSeek官方API的开发验证配置。它在 `tuned.yaml` 的漂移与训练参数基础上开启受控LLM策略，并设置调用次数、单次预留Token、置信度门槛和调用冷却。

该配置：

- 只用于开发验证；
- 只从 `DEEPSEEK_API_KEY` 环境变量读取密钥；
- API不可用时自动退回规则策略；
- 不应直接用于正式离线比赛镜像。

## 每份配置控制的模块

| 配置块 | 控制对象 |
|---|---|
| `stream` | 初始样本、窗口大小、漂移出现时间 |
| `monitoring` | PSI、KS、性能下降和标签漂移阈值 |
| `policy` | 连续确认、冷却期和回滚条件 |
| `training` | 回放容量、近期数据比例和留出比例 |
| `validation` | 候选上线收益和历史退化上限 |
| `budget` | 更新次数、训练秒数、标签和Token预算 |
| `llm` | DeepSeek开关、模型、API地址、调用上限、置信度与Token限制 |
| `tracking` | 运行结果目录和SwanLab开关 |

## 是否需要人工修改

需要。官方数据发布后，主要调参工作会集中在此目录。

## 正式提交时是否保留

必须保留。正式镜像应明确指定一份冻结的比赛配置，例如以后增加：

```text
configs\competition.yaml
```

# 七、`runs`：运行结果与实验记录

完整路径：

```text
D:\industrial_evolution\runs
```

## 主要作用

每执行一次程序，就创建一个独立运行目录。不同实验不会相互覆盖。

目录名称示例：

```text
run-20261029-074753-7aa3dc
```

名称包含：

- 运行日期；
- 运行时间；
- 随机编号。

## 每个 `run-*` 目录

标准结构：

```text
run-日期时间-编号\
├── events.jsonl
├── metrics.csv
├── summary.json
└── models\
```

### `events.jsonl`

完整事件流水，记录：

- 状态机迁移；
- 漂移诊断；
- 更新决策；
- 候选训练；
- 上线或拒绝；
- 回滚；
- 安全兜底；
- 运行完成。

每行是一条独立JSON事件，即使程序中途停止，也能保留之前已经写入的事件。

### `metrics.csv`

每个数据窗口一行，适合Excel、Pandas和绘图工具查看。

记录：

- 当前评分模型版本和动作后的部署版本；
- 漂移类型和漂移强度；
- 系统动作及结构化失败状态；
- 候选提升；
- 累计训练时间；
- 累计首次标签访问和Token使用量。

### `summary.json`

整次实验摘要，记录：

- 处理窗口数和成功窗口数；
- 训练、上线、拒绝和回滚次数；
- 初始、平均和最终在线指标；
- 与最终分数配对的模型版本；
- 运行结束时实际部署版本；
- 总预算使用情况和预算违规计数。

### `models` 子目录

保存该次运行产生的模型版本。

标准内容：

```text
models\
├── registry.json
├── v000.joblib
├── v001.joblib
└── v002.joblib
```

- `registry.json`：记录当前champion、版本来源和父版本；
- `v000.joblib`：初始模型；
- `v001.joblib`以后：成功上线的候选模型。

被拒绝的候选不会注册为正式模型版本，但其评估结果会留在事件日志中。

## `runs\round2-runs`

这是第二轮120窗口压力测试的专用结果目录。

包含：

- `round2-before`：PSI缓存优化前；
- `round2-after`：PSI缓存优化后。

项目根部的以下文件也是性能分析产物：

```text
runs\round1-before.prof
runs\round1-after.prof
runs\round2-before.prof
runs\round2-after.prof
runs\round2-before.json
runs\round2-after.json
```

`.prof`可以使用Python `pstats`分析函数耗时。

## 是否需要人工修改

不要手工修改运行结果，否则会破坏实验可信度。需要分析时应读取或复制。

## 是否可以删除

可以删除不再需要的旧实验，但建议保留：

- 静态基线；
- 最佳自进化结果；
- 自动回滚演示；
- 三轮优化的前后对照；
- 正式报告引用的实验。

## 正式提交时是否保留

通常不把所有本地运行目录放进镜像。正式实验记录应上传SwanLab，并保留少量必要示例或由平台运行时重新生成。

# 九、`src\industrial_evolution`：核心程序包

完整路径：

```text
D:\industrial_evolution\src\industrial_evolution
```

## 主要作用

这是系统核心。它负责把数据、检测、决策、训练、评估、版本管理和记录串联为无人干预的闭环。

# 十、`data`：数据流与输入验证

完整路径：

```text
src\industrial_evolution\data
```

## 主要作用

把不同来源的数据统一转换为系统认识的 `DataWindow`。

系统其他模块不需要知道数据来自：

- 合成演示；
- CSV；
- 官方评测SDK；
- 实时消息队列；
- 文件目录。

它们只需要接收统一窗口。

## 当前文件

### `synthetic.py`

生成可重复的合成工业数据流，包括：

- 稳定阶段；
- 渐进漂移；
- 突发漂移；
- 特征分布变化；
- 概念关系变化；
- 标签噪声。

主要用于开发、测试和答辩演示，不能代替官方数据。

### `stream.py`

实现CSV顺序数据流，负责：

- 检查CSV文件存在；
- 分块预检目标列、删除列和数据类型；
- 为样本分配稳定全局ID；
- 拒绝目标缺失、特征无穷值和零完整窗口；
- 使用有界内存按原始行顺序拼装窗口；
- 保证先预测、后更新的时间顺序。

### `__init__.py`

把目录声明为Python包。

## 正式比赛中的变化

官方SDK发布后，应在这里新增类似：

```text
official_stream.py
```

把官方隐藏测试流转换为 `DataWindow`，而不是修改漂移、训练和评估模块。

# 十一、`monitoring`：漂移监测与归因

完整路径：

```text
src\industrial_evolution\monitoring
```

## 主要作用

回答三个问题：

1. 数据是否发生变化；
2. 模型性能是否下降；
3. 变化可能属于哪种漂移。

## 当前文件

### `feature_drift.py`

监测输入特征分布，计算：

- PSI；
- KS统计量；
- Wasserstein距离；
- 每个特征严重度；
- 漂移最明显的前三个特征；
- 整体输入漂移分数。

该模块缓存参考分布统计量，只在参考数据更新时重建，避免长流中重复计算。

### `performance_drift.py`

监测模型真实性能变化，包括：

- 当前窗口指标；
- 滚动窗口平均指标；
- 相对基准的性能下降；
- Page-Hinkley连续变化告警。

### `diagnosis.py`

综合输入、性能和完整类别分布，输出：

- `none`；
- `covariate`；
- `label`；
- `concept_suspected`；
- `mixed`。

同时生成可读的中文诊断原因。

### `__init__.py`

声明监测子包。

# 十二、`policy`：更新决策策略

完整路径：

```text
src\industrial_evolution\policy
```

## 主要作用

把漂移报告转换为可执行动作。

当前动作包括：

- `NO_UPDATE`：不更新；
- `RETRAIN_WITH_REPLAY`：使用回放数据训练候选；
- `ROLLBACK`：恢复上一稳定模型。

## 当前文件

### `rule_policy.py`

规则策略负责：

- 漂移连续窗口确认；
- 更新冷却期；
- 检查训练预算结果；
- 输出动作和原因；
- 记录上次更新时间。

### `hybrid_policy.py`

受控混合策略始终先执行 `RuleBasedPolicy`。只有规则已经建议训练时，它才允许DeepSeek进行一次二选一判断。

它负责：

- 限制LLM最大调用次数和Token预算；
- 拒绝低置信度响应；
- 缓存短期否决，避免连续消耗Token；
- API异常或输出无效时退回原规则动作；
- 将实际usage和延迟交给编排器记录；
- 把训练后的冷却状态同步回规则策略。

DeepSeek不能绕过预算、候选评估或自动回滚。

# 十二-A、`llm`：受控大模型提供商

完整路径：

```text
src\industrial_evolution\llm
```

## 主要作用

将DeepSeek调用隔离在可替换提供商接口后，只传递结构化漂移和预算摘要，并把响应限制为白名单动作。

## 当前文件

### `provider.py`

定义与厂商无关的：

- `LLMDecisionRequest`：窗口、漂移、性能和剩余预算摘要；
- `LLMDecisionResponse`：动作、置信度、理由、模型、Token和延迟；
- `PolicyLLMProvider`：提供商必须实现的协议。

正式 Harness 使用 Qwen3.8 27B 或 4B；如需后训练，可选择基于 Qwen 使用 PyTRiO。具体模型服务协议按赛方资料接入，不猜测接口。

### `schemas.py`

使用Pydantic严格校验模型JSON，只允许：

```text
no_update
retrain_with_replay
```

多余字段、空理由、置信度越界和非法动作都会被拒绝。

### `deepseek_provider.py`

负责：

- 从 `DEEPSEEK_API_KEY` 环境变量读取密钥；
- 延迟创建OpenAI兼容客户端；
- 调用 `https://api.deepseek.com`；
- 请求JSON模式输出；
- 解析输入、输出、推理和总Token；
- 把厂商错误转换为不暴露密钥和请求正文的安全异常。

### `__init__.py`

声明受控LLM子包。

完整路径：

## 主要作用

# 十七、`tracking`：实验记录与外部平台镜像

完整路径：

```text
src\industrial_evolution\tracking
```

## 主要作用

让系统的每一个决定可观察、可复现、可解释。

## 当前文件

### `local_tracker.py`

本地记录器负责：

- 创建独立运行目录；
- 逐条追加 `events.jsonl`；
- 逐窗口追加 `metrics.csv`；
- 写入 `summary.json`；
- 转换枚举、Path和NumPy数值为JSON可保存格式。

指标采用追加写入，不会随着窗口数增加反复重写整个文件。

### `swanlab_tracker.py`

包含两个部分：

#### `SwanLabTracker`

将事件、数值指标、判断链和运行产物同步到SwanLab，记录分三层：

| 层 | 方法 | 内容 |
|---|---|---|
| 曲线 | `log_metrics` | 每窗口得分、漂移量、动作、预算消耗，`step` 取窗口序号，多轮可叠加对比 |
| 文本 | `log_event` / `log_hypothesis` | 关键事件，以及每窗口"观察→诊断→决策→预期→结果→判定"的假设链 |
| 产物 | `close` | `summary.json`、`metrics.csv`、`events.jsonl`、模型注册表上传为 run 文件 |

判定分四档：`supported` / `refuted` / `inconclusive` / `not_applicable`。被否定的候选同样
入库，负结果不丢——这是"实验规范"分项要看的东西。

三种上传形态：`online`（云端）、`local`（本机看板）、`offline`（落盘待 `swanlab sync`）。
无凭证时 `online` 自动降级为 `offline`，避免卡在交互登录提示上（实测 ConPTY 下
`isatty()` 返回真，SwanLab 会等标准输入）。

#### `CompositeTracker`

先保证本地记录，再把数据分发给可选镜像。`close` 的顺序是**先写本地 `summary.json`，
再让镜像上传**，保证看板掉线时本地证据仍然完整。SwanLab 等外部记录器失败时：

- 记录 `tracker_mirror_failure`（带连续失败次数）；
- 连续失败达到 `MIRROR_FAILURE_LIMIT=5` 才记录 `tracker_mirror_disabled` 并停用该镜像，
  偶发网络抖动不会把镜像永久踢掉；
- 不影响本地核心流程。

完整用法见 `docs\SwanLab记录使用说明.md`。

# 二十、哪些目录可以清理，哪些不能

| 目录 | 是否可删除 | 说明 |
|---|---|---|
| `.pytest_cache` | 可以 | 测试会自动重建 |
| `__pycache__` | 可以 | Python会自动重建 |
| `src\industrial_evolution.egg-info` | 可以 | 重新安装项目会生成 |
| `.venv` | 可以但需重建 | 删除后必须重新安装依赖 |
| `runs`中的旧实验 | 可以选择性删除 | 保留基线、最佳结果和正式报告引用实验 |
| `configs` | 不要删除 | 系统运行参数 |
| `docs` | 不要删除 | 用户和提交文档 |
| `src\industrial_evolution` | 不要删除 | 核心代码 |
| `tests` | 不要删除 | 质量保障和回归依据 |
