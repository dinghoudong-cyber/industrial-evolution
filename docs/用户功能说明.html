Start

最快的使用方式

打开 D:\industrial_evolution，双击 运行演示.bat。程序会使用调优配置依次模拟稳定、渐进漂移和突发漂移三个阶段。

cd D:\industrial_evolution
.\.venv\Scripts\python.exe -m industrial_evolution.cli demo `
  --config configs\tuned.yaml

D:\industrial_evolution\runs\run-日期时间-编号
Process

一次运行中会发生什么

先预测，后训练

每个窗口先由当前 champion 预测和评分，再允许使用窗口数据训练，避免未来信息泄漏。

三路漂移证据

PSI、KS、Wasserstein 与非有限值比例检查输入分布和数据质量；滚动指标和 Page-Hinkley 检查性能；分类任务同时检查完整类别分布。

预算内做决定

连续确认、冷却期、更新次数、训练秒数、标签和 Token 预算共同决定是否训练。

回放训练

近期样本用于适应新工况，历史代表样本用于降低灾难性遗忘。

双重上线门槛

候选模型既要在近期留出集提升，也不能让历史守护集退化过多。

持续回滚保护

上线后若连续退化，系统同时恢复上一稳定模型、性能基线、特征参考、标签参考和策略状态。

训练成功不等于允许上线。 新模型可能因近期提升不足或历史工况退化过大而被安全拒绝。

Profiles

四套配置怎么选择

tuned.yaml

直接演示。针对当前合成流调优，响应更快，默认离线。

default.yaml

通用起点。策略更保守，适合接入新数据后重新校准。

static.yaml

禁止更新。用于证明自进化系统是否优于静态部署。

deepseek-dev.yaml

仅用于DeepSeek开发验证。API异常时自动回退到规则策略。

关键参数控制什么
consecutive_windows漂移需要连续出现多少个窗口才行动
cooldown_windows更新后等待多久才能再次训练
recent_fraction近期数据在候选训练中的比例
min_improvement候选上线所需的最小近期提升
max_historical_drop允许候选在历史守护集上退化多少
rollback_drop上线后触发回滚的性能差值
Data

接入自己的 CSV

CSV 原始行顺序必须代表时间顺序。特征必须是数值列，可有缺失值但不能包含无穷值；分类目标允许离散数值或字符串类别，回归目标必须是有限数值。时间戳、字符串编号等特征应使用 --drop-column 排除。

.\.venv\Scripts\python.exe -m industrial_evolution.cli run-csv `
  --csv D:\数据\train.csv `
  --target label `
  --initial-size 1000 `
  --window-size 200 `
  --drop-column timestamp
  • initial-size：最前面用于初始模型的行数。
  • window-size：后续每个流式窗口的行数。
  • target：真实标签所在列。
Evidence

如何查看运行结果

summary.json

整次运行摘要：窗口数、完整/部分/失败状态、训练次数、上线、拒绝、回滚、平均指标和预算。

metrics.csv

每个窗口一行，可用 Excel 查看漂移、动作、分数和累计成本。

events.jsonl

完整事件流水，回答何时发现漂移、为什么训练、为什么拒绝。

models\

保存模型文件和 registry.json，标明当前 champion 及每个版本来源。

这些数字只用于验证合成数据闭环，不能代表官方隐藏测试成绩。

Control

安全与成本机制

  1. 预算账本：标签首次用于评分、验证或训练时计费并按样本ID去重；训练和 Token 在动作前检查额度。
  2. 冷却期：避免同一段漂移反复触发训练。
  3. 独立历史守护集：守护样本永不进入训练回放，阻止验证泄漏。
  4. 完整状态回滚：模型及全部监测参考一起恢复。
  5. 原子写入：模型和注册表先写临时文件，再替换正式文件。
  6. 可选服务隔离：SwanLab 失败会降级，不中断本地核心流程。
LLM Guardrail

DeepSeek 开发接入

DeepSeek只在规则策略已经确认漂移成立、冷却结束且训练预算允许后参与开发调试。正式 Harness 使用赛方建议的 Qwen3.8 27B 或 4B；PyTRiO 可作为 Qwen 的可选后训练路径，具体服务 ID 与接口以赛方资料为准。

默认完全离线

tuned.yaml、default.yaml 和 static.yaml 均不联网，Token为0。

显式开发配置

只有使用 configs\deepseek-dev.yaml 才启用DeepSeek。正式 Harness 使用赛方建议的 Qwen3.8 27B 或 4B；PyTRiO 可选用于后训练。若提交后训练模型，模型 ID 和 API Key 按平台要求通过安全渠道提交。

秘密不落盘

密钥仅从 DEEPSEEK_API_KEY 环境变量读取，不得写入YAML、代码、文档、聊天或Git。

失败自动回退

密钥缺失、超时、限流、非法JSON或低置信度时使用原规则策略继续运行。

Troubleshooting

常见问题

没有发生更新

可能是漂移未达阈值、还在冷却期、候选提升不足、历史退化过大或预算耗尽。查看 metrics.csv 的 reason 列。

CSV 目标列不存在

检查 --target 与 CSV 第一行是否完全一致，包括大小写和空格。

只接受数值特征

删除时间戳和字符串列，或先编码类别特征。

SwanLab 不可用

本地运行仍会继续，并记录 tracker_mirror_failure 或 swanlab_disabled。

终端中文乱码

通常只是显示编码问题。结果文件统一为 UTF-8，CSV 首行带 BOM。

final_score 的含义

它是最后成功窗口上、更新前模型的流式表现；final_score_model_version 与其配对，final_deployed_model_version 表示运行结束时实际部署版本。

Structure

项目文件夹怎么分工

文件夹主要职责是否人工维护
configs\漂移阈值、更新策略、训练比例、上线门槛和预算需要
