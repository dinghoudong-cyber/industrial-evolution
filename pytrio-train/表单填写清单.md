## 四、「合规率」和「一致率」分别是什么意思

- **输出合规率**：模型返回的文本能否按 Harness 的 schema 解析——必须是单个 JSON 对象，
  只含 `action` / `confidence` / `reason` 三个字段，`action ∈ {no_update, retrain_with_replay}`，
  `confidence ∈ [0,1]`，`reason` 长度 1–120。
- **与规则一致率**：解析出的 `action` 是否等于训练目标（规则策略的决策）。

两者都不算「效果提升」。微调目标是让模型**稳定复现**规则策略的输出格式与决策，
不是超越规则。对外表述必须区分清楚。

## 五、验证中发现的两个真实现象（如实记录）

1. **结束符污染**。用原始 tokenizer 采样时，返回文本尾部带 `<|im_end|>`，
   直接 `json.loads` 会报 `Extra data`。走 OpenAI 兼容 HTTP 接口不会出现这个字符，
   所以 `verify_sampler.py` 按线上口径剥掉后再解析。
2. **`reason` 偶发超长**。第 2 轮出现 1 条 122 字（上限 120）。训练数据里最长恰好 120、
   无超限样本，说明是模型自身生成的轻微越界。线上 Harness 会判为不合法并回落规则策略，
   属于设计好的安全路径，不是崩溃。

| 产物 | 类型 | 能否填 |

| sklearn 训练出的 `.pkl` | 工业模型产物 | 否 |

## 七、复现命令

```bash
# 训练（三轮，需 PYTRIO_API_KEY 环境变量）
python pytrio-train/smoke_train.py --base-model Qwen/Qwen3.8-27B \
  --data pytrio-train/sft_data.jsonl --steps 100 --batch-size 2 \
  --save-state round1 --weight-name sampler-r1 --offset 0 --swanlab

python pytrio-train/smoke_train.py --resume 'trio://.../weights/round1' \
  --data pytrio-train/sft_data.jsonl --steps 100 --batch-size 2 \
  --save-state round2 --weight-name sampler-r2 --offset 200 --swanlab

python pytrio-train/smoke_train.py --resume 'trio://.../weights/round2' \
  --data pytrio-train/sft_data.jsonl --steps 100 --batch-size 2 \
  --save-state round3 --weight-name sampler-r3 --offset 400 --swanlab

# 验证（权重可调用 + 输出合规）
python pytrio-train/verify_sampler.py --base-model Qwen/Qwen3.8-27B \
  --model-path 'trio://run_n7w9j6kns8cp/sampler_weights/sampler-r3' --samples 30
```
